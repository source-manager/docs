    source-manager¶

    A desktop GUI for viewing and managing Git repositories, on macOS, Linux and Windows. Built with Qt/QML and libgit2 — one native window, no browser engine, no daemon.

    It is a full client rather than a viewer: it stages at line level, rewrites history, resolves conflicts, moves objects over the network, reads pull requests and CI from three forges, and tells you what it did afterwards.

    What it does, in one screenful¶
    A fleet home Every registered repository's branch, drift, uncommitted work and stopped operations on one page — grouped, and filled by scanning a folder
    History A branch graph with lanes and ref pills, searchable six ways including the content a commit changed, filterable by author, period, ref and signature
    Staging File, hunk or individual line — and discard and revert at the same three granularities
    Rewriting Interactive rebase you plan before anything is written, amend, reword or edit any commit, cherry-pick a commit or a range
    Conflicts Three-way per hunk, showing what the current choice would actually write, with an external merge tool beside it
    Transport Fetch, push, pull and clone, off the interface thread, one at a time, with force-with-lease and a plain force behind a third gesture
    Forges Pull requests, reviews, line comments and CI from GitHub, GitLab and Bitbucket, including self-hosted instances
    Trackers Tickets read and written from GitHub Issues, Jira or Linear — and link rules that need no key at all
    Insights History metrics, DORA with the definition printed beside every figure, per-person figures with the caveat kept, CI health
    Keyboard A ⌘K palette and a two-press hint overlay, both fed by one registry every control registers itself with
    Honesty An operation log that types each write and offers a way back only where one exists — and says plainly when there is not

    The five things nothing else in the field does¶

    1. Honest undo. Every operation is typed — ref-move, inverse, destructive, remote, none — and a way back is offered only where one can be kept, with file-level backups taken before the writes that destroy content held in no git object. See Undo, backups and the log.
    2. It teaches the command line. The git command you would have typed is printed beside the decision, and the CLI vocabulary is the palette's own search index — so searching stash push finds the button.
    3. Repository insights. History metrics, DORA, team and per-person figures, CI health, each figure carrying the definition that produced it. This is normally a separate SaaS product. See Repository metrics.
    4. The keyboard model. A palette and a two-press, usage-ranked hint overlay, with an audit test that fails the build when a control is reachable by neither route.
    5. A review draft that survives. Write a review over several minutes and it survives the network failing, the app closing and signing out — with the forge's own pending review visible in the diff and marked as unsent.

    What it deliberately does not do¶

    Absences here are positions rather than backlog, and each is argued rather than asserted:

    • No "Undo everything" button — the reflog records refs, not files, and a button that cannot tell those apart is most confident when it is most wrong.
    • No agentic AI — nothing edits files, runs commands or takes several turns. Generation produces a draft a reader reviews before it is used.
    • No embedded terminal and no Explorer shell extension — both declined with the cost written down. See Closed as decisions.
    • No branch picker that checks out — the breadcrumb's picker narrows the history and people rely on it not moving HEAD.
    • Absent rather than greyed controls: a verb that cannot apply to this repository is not drawn at all.

    Honesty about what is proven¶

    The project's own documentation draws a line between what is implemented and what has been exercised, and these docs keep it. Three things are proved in shape and never against the real thing:

    Unverified surfaces

    • Windows has never been executed. CI proves the tree configures, compiles, links and passes the suite headless under MSVC — and nothing about window chrome, native choosers, high-DPI on a real display, or paths typed with a drive letter.
    • GitLab and Bitbucket are fixture-proved. Their tests pin the URLs built and the JSON mapped onto the documented fields; no live instance has ever answered.
    • The AI providers, x509 signing, both keychain backends and the sparse verbs are implemented and unexercised.

    Every page that touches one of those repeats the caveat where the claim is made.

    Everything a single repository needs to be worked in day to day is free, permanently — staging, committing, history, blame, branching, merging, transport, conflict resolution, stashing, and the interactive rebase.
