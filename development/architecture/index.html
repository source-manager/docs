    Architecture¶

    An orientation. AGENTS.md is the authority and goes into far more depth; this page is the shape of the thing and the handful of structural decisions that explain the rest.

    The tree¶

    src/
├── main.cpp            entry point; builds the services and the first window
├── core/               the manager, and state that outlives a repository
├── git/                one controller per git operation, plus the diff parser
├── forge/              pull requests and CI over HTTP, behind a provider seam
├── ai/                 asking a model something, behind its own seam
├── licence/            a licence check, and nothing about this product
└── palette/            a command palette, and nothing about this app

qml/
├── design/             tokens, singletons and primitives. Imports nothing
├── parts/              what the surfaces are built from
├── surfaces/           one file per destination
└── shell/              the window, and the frame around a surface

tests/                  one executable per test class, plus the QML suites

    src/ is the single include root, so every local include names its layer, and a test spells it the same way.

    The first four folders are a reading aid rather than a link boundary: the backend is one static library filled by a source list per folder, because the manager owns a controller from each and the tests link one target.

    Two directories are the exception, and the exception is the feature¶

    palette/ and licence/ are each their own library target — the first linking Qt Core and Qml, the second Qt Core and libcrypto, and neither linking the rest of the app. So a file in either that reached for a repository, a preference or one of this app's commands would not compile.

    That is what makes "it knows nothing about this application" a fact the build enforces instead of a claim in a comment.

    The palette was a sort comparator and a rank table written in a QML file — which is to say logic no C++ test could reach, asserted only through a window somebody had to build. Its vocabulary names no domain: a row is an id, a title, a subtitle, keywords, a group, a note, and two numbers that order an untyped list. It cannot run anything and deliberately never gains the ability: there is no callback on a row, it announces an id, and the host decides what that means.

    The licence check carries the key format, the signature, the three places a key may be kept, and coverage against the build date. What a product is — its key prefix, its public keys, its feature table — is data, and this app's is nine lines. Its own test drives it as a different product would, inventing one with its own prefix and features, because that is the only thing that can say the package is reusable.

    The backend¶

    The controllers are Qt Core only, with no GUI dependency — that is what lets the tests exercise them without a GUI application object. Everything a window needs is built once and handed to a window factory, which creates one manager per window and exposes it to that window's own context.

    A manager owns every controller that is about a repository; nine members that are about the reader are shared between windows — the preferences, the fleet, the command counts, the language, the editor template, the keychain, the snapshot store, the command spellings and the version. Two of any of those in one process would be either a divergence or a race, since every one is backed by a file.

    Each controller opens its own repository handle per call, through one owning type that closes it on scope exit. Twenty-two controllers used to have a private copy of that open, and underneath them were 357 hand-written frees — one per exit from every function that opened one, so every early return was a leak audited by eye.

    What joins the general refresh, and what does not¶

    refreshAll() runs after every staged hunk, on every working-tree watcher event, and whenever the window comes back to the foreground. Anything in it is paid at that rate.

    So the rule is both halves: an O(history) walk is batched against a time budget and asked for by the surface that draws it. The file history, the reflog, the metrics, the comparison, the commit-message vocabulary and the subtree list are all outside it.

    "One commit message per commit and no diff" is a statement about the per-commit cost and not about the total, and it is what let a twenty-thousand-commit walk into the refresh under a comment calling it "the same order of work as the tag list". A tag list is O(refs).

    The fleet is deliberately outside it too: summarising it opens every registered repository.

    The interface¶

    Exactly one surface exists at a time. Surfaces are loaded on demand rather than stacked: History and Blame each hold thousands of rows, and there is no reason for the ones you are not looking at to exist.

    No surface reaches up into the window. Shared state travels down as properties and back up as signals, which is what lets any surface be instantiated on its own in a test — an id reference into the window would compile fine and break only under test.

    The import graph is acyclic and worth keeping so: design imports nothing, parts imports design, surfaces imports both, and shell imports design plus, in three files, the other two. Those three are a widening rather than a cycle, and each is there for a shared element.

    Colours come from one place. Not a hex literal and not a computed colour anywhere else — that rule used to be taste and is now load-bearing: forty-five inline colour calls spelled out one palette's ink and accent at some alpha, and every one of them was a component that would have gone on drawing the dark theme after the palette changed.

    Do not name a component after a Controls type. An explicit module import beats the implicit same-directory one, so the stock type wins — silently, rendering system chrome. That is why the tick is TickBox and the command type is Command.

    Two things every control does¶

    It registers itself. The palette and the hint overlay used to be two hand-maintained lists and they drifted — elements got a hint but no palette entry, or neither, and one whole tab strip had nothing at all. Now the design system's button, chip, row, tick and field each declare a command for themselves, so anything built out of them is covered without a thought.

    It says what it does. One restyled tooltip, drawn from the title and detail the control already registered. Nothing new is written anywhere, which is the point rather than a convenience: a separate tooltip property would be a third wording of one thing, and the drift between what the palette says and what the pointer says would be invisible, since nobody reads both at once.

    Both are structural: one audit test walks the built interface on eight surfaces and fails, by name, on anything interactive that registered neither route; a second fails on any control that is drawn and has nothing to say.

    The three performance shapes¶

    Every expensive thing here is one of three, and a new one should be one of them too.

    Batched against a time budget. A walk runs a batch per turn of the event loop against a millisecond budget rather than a count, because what an item costs varies by orders of magnitude — comparing a field against diffing a large file. A turn always does at least one item, whatever the budget says, or a budget of zero spins for ever making no progress.

    Virtualised, with a height known at creation. A list fills its viewport by creating rows until their heights add up to it, and a row whose height is not known when it is created never adds anything up — so slicing a long hunk into smaller pieces made it strictly worse at every size. What virtualisation needs is not smaller rows but rows whose height is arithmetic.

    Its corollary: a list's own height must not be bound to what the built rows add up to, or it starts at zero, builds no rows, and stays at zero.

    One operation over a set, never N operations. Discarding eight hundred files was eight hundred repository opens, status walks, index writes, snapshots, log rows and full refreshes — none of those costs is per file, and every one is per operation. All four such verbs go through one shared sweep with one budget, one progress row and one Stop that is never gated.

    The seams¶

    forge/ and ai/ are each a provider interface with a registry, so adding one is a class and one registration line — with the surfaces written against documented field lists rather than against anybody's JSON.

    That claim is tested rather than asserted: adding a second forge proved it for every surface and every field list, and falsified it for the transport's write allow-list, which a provider deliberately cannot add a row to. The header says so now. A third forge, shaped differently in three ways, is what actually tested the seam — different paging, no review object at all, and both readings of CI.

    The AI seam's claim is narrower and says so: a provider cannot widen what may leave the machine, because the privacy gate reads the URL rather than anything a provider declares.

    Every transport is an interface because the tests cannot reach the network, and every implementation must answer on a later turn even when it already holds the answer — or a surface would pass its tests without ever rendering the loading state it spends most of its life in.
