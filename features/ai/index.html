    Asking a model¶

    Licensing — Paid. This page is ai. You still supply the key or the local model. What a licence adds

    Bring-your-own-key and local models only. No vendor credits, no account, nothing this project resells. Two consequences run through everything below: the app has to be useful with no key at all, so local models are the default path and were written first; and a key that does exist is kept the way the git credential ladder keeps one.

    This reverses a documented position, and the argument is worth reading

    The project once recorded that no commit subject would be generated from a diff, because "describing what a change does is the one part of a message not derivable from what changed, and a plausible sentence there would be the most confident lie the app could tell".

    Every clause of that is still true. What it did not credit is the safeguard: the reader reviews the sentence before it is committed. A generated subject lands in the box a press away from being changed, marked as generated and naming the model that wrote it, beside a Commit button nobody presses by accident. A lie somebody reads and declines is a draft.

    So the line moved rather than went. What stays refused is anything written without a reader in front of it — nothing is generated on a refresh, on a timer, or as a side effect of reading, and no generated string is committed, pushed or applied by the same press that produced it.

    Four providers¶

    Local? Needs a key?
    Ollama on this machine no
    LM Studio on this machine no
    OpenAI hosted yes
    Anthropic hosted yes

    The local pair are the default and were written first, so the offline path is the one that gets exercised rather than the fallback nobody runs.

    Ollama goes through its own API rather than its compatibility one, which costs a class and buys three things the shim flattens: which model actually answered, which models have been pulled rather than which could be, and a 404 that means a missing model rather than a missing path — the commonest first failure anybody meets here.

    Anthropic is the one that proves the seam. Three things there are not the OpenAI shape at all: system is a top-level field rather than a message with a role (sent as a message it is silently demoted to a user turn, which is the failure that looks like the model ignoring its instructions); max_tokens is required; and the reply's content is a list of blocks, of which only the text ones are joined.

    Adding a provider is a class and one registration line — and where that claim is narrower than the forge seam's is stated: a provider cannot widen what may leave the machine, because the gate reads the URL rather than anything a provider declares.

    The privacy gate¶

    A hosted model means somebody's private diff leaves the machine, so configuring a key is not consent to send this repository.

    Two answers, and the repository's wins:

    • A global default, and it is the one setting in this app that starts off. Everywhere else the argument is that a thing somebody has to switch on is a thing for people who already know it is there; here what is being defaulted is whether your private diff leaves your machine, and there is no reading of "sensible default" that answers yes to that on your behalf.
    • A per-repository answer in that repository's own .git/config, which is not cloned, so a consent cannot arrive with somebody else's branch. Three values and never two — absent, yes and no — because a repository that has said no must not be overruled by the global saying yes.

    A request to a non-local host is refused before it is made, and that is enforced in the transport rather than in the controller that decides — a decision taken in a controller is one a caller can be written around, and the claim being made is that no request is made, which only the thing that opens sockets can promise. A test drives every verb with the gate shut and requires the request log to come back empty.

    What counts as this machine is loopback and nothing else. A LAN address is another machine: "it only went to the box under my desk" is not a promise that check is in a position to make. And a URL carrying userinfo is never local whatever its host, because http://127.0.0.1@evil/ is the one shape that gets this question answered wrongly.

    The endpoint decides, never the provider's "I am local" flag: somebody who has repointed Ollama at a machine on their network is sending a diff off this one.

    It is deliberately not a list of allowed hosts: the endpoints are typed by you — a private Ollama on another machine on the LAN is an ordinary thing to point this at — so a literal allow-list would be either wrong for that reader or so wide as to say nothing.

    What may be sent, and how much¶

    Every prompt carries a piece of a repository and none of it can be handed over whole: a diff has no upper bound, and what leaves the machine should be the smallest thing that answers the question.

    So everything is bounded and says so in the material itself, not merely beside it — the model is that string's reader, and one handed half a diff with nothing saying so will describe the half it got as though it were the change. You are told too: the answer carries whether the material was cut short, because a message written from part of a change reads exactly like one written from all of it.

    The ceiling is deliberately not configurable: raising it is choosing to send more of a repository somewhere.

    Nothing is asked for automatically¶

    Not on a refresh, not on a timer, not as a side effect of reading, and not because a surface was built. The model list is bought by opening the setup dialog rather than by arriving anywhere.

    That is a property of the callers rather than of any type, so it is asserted rather than described: a test drives every refresh path there is and requires the request log empty.

    Three switches, and one deliberate exception¶

    • The feature switch. Off, every AI control is absent — off the screen, and therefore out of the palette and off the hint keys too. The app is exactly what it was before any of this existed.
    • Configured. With no provider chosen the controls stay drawn, and pressing one opens the setup dialog. That is the exception, and it follows the external-tools line: absent-not-greyed is for what this repository cannot do, not for what the app has not been told yet. A control missing for a reason you could settle in ten seconds is a feature you never discover; one that explains itself when pressed is not. It stays enabled for the same reason — a disabled control cannot explain why it is disabled.
    • The remote gate, above.

    Twelve verbs¶

    Each offered beside the thing it drafts, and none of them replacing a field:

    Verb Where
    A commit message, and the @ai placeholder The commit box
    A reworded commit message A commit's menu
    Grouping the working tree into several commits Changes
    An explanation of one commit A commit's menu
    A changelog since a commit A commit's menu
    A summary of what happened over a period History
    A proposal's title and description The propose dialog
    A branch name The new-branch dialog
    A stash description The stash box
    A commit message for a split part Splitting a branch
    A free-form question, with saved prompts Changes and History
    A conflict resolution, per hunk Conflicts

    @ai is the best shape in the field, and is why the commit verb takes a hint: you write the half that carries intent, mark where the machine should fill in, and the two are blended rather than one replacing the other. Without the placeholder the hint is empty — passing the box's contents there would quietly turn every generation into a rewrite of whatever was in it.

    The changelog is the one verb the old refusal never covered. It summarises what people wrote rather than inventing intent, and its prompt says so: use only what the messages say, infer nothing they do not.

    The activity summary is its sibling and is a different question. A changelog is asked of two commits and is written for somebody else, so it leaves out what a reader of release notes would not want. "What happened this week" is asked of a clock and is written for the person who was there, so nothing is left out for being unremarkable. Three consequences: it reads HEAD's own history rather than the list on screen and says so (answering a period from a list narrowed to one author would answer a different question quietly); a commit outside the window is skipped and never a reason to stop, since the ordering is topological as well as by time; and merges are left out, both sides being reached on their own.

    The composer proposes and performs nothing. What it proposes is several commits, so you have to be able to disagree with the grouping before any of them exists. Each group is committed on its own press, and anything not committed stays exactly where it was.

    Prompt presets encode a repository's message convention — Conventional Commits, Gitmoji, or plain prose — with this repository's own vocabulary woven in from what has already been read out of the log and any commitlint config. A log with no scopes is told to use none, because inventing one is the app deciding how somebody else's log reads.

    Every generated string says so, and names what wrote it¶

    This is the house rule that an inferred thing names its evidence, and it matters more here than anywhere else in the app: what makes generation defensible is that a reader reviews it, and a reader cannot review what they do not know is a draft.

    The model travels with the answer rather than being read off the controller when it is drawn — a label taken from the settings page goes wrong the moment somebody changes the drop-down while an answer is on screen. And it names the model that answered, which is not always the one asked for: LM Studio serves whatever is loaded and reports it back.

    Nothing in the AI layer writes to a repository¶

    Not one verb. Text is generated into a slot and a surface hands it to the controller that owns the write, which is why the AI reword inherits the rebase's refusals, its published-commit warning and its sentence about how many commits get new hashes. A second write path here would be a second answer to what rewording means, and it would be the one with no refusals in it.

    That is also what makes the record honest: the operation log records only what writes, and those rows are the ones the controllers that performed the write already record, in their own words. Generating text that lands in a box for review is not a repository operation.

    No git command is printed for any of these. Git has no verb for asking a model, and an invented one is a command somebody pastes.

    Four states, and a slot¶

    Idle, asking, ready, failed — and every refusal lands in the panel rather than only in the toast, which the first version got wrong: "no repository is open" went to the toast alone, leaving the panel drawing nothing at all, indistinguishable from a control nobody had pressed.

    Requests carry an epoch, bumped by a cancel and by the repository changing. The forge layer needs one so a stale list does not land on the wrong repository; here it is worse, because a description of one project's diff landing in another project's commit box is a box somebody presses Commit on.

    Cancelling keeps what has already been answered and settles what was in flight as idle rather than failed — you stopped it, and reporting your own press back to you as an error is not news.

    What is not built¶

    • No streaming. A single complete answer, with an asking state while it is in flight. Streaming would cost a second shape on the transport, on the replay and on every surface that draws a partial answer, and what it buys is watching a sentence appear rather than waiting a moment — worth less here than in a chat client, because none of these answers is long and every one of them is reviewed before it is used.
    • No agentic anything. Nothing runs a command, edits a file, or takes more than one turn. The one verb whose output is code is offered as a side to be chosen. See Deliberate non-goals.
    • No auto-resolving "mechanical" conflicts. The failure mode is silent by construction — see Merging and conflicts.

    Fixture-proved and never live-proved

    There is no model to reach from the test suite — the sandbox denies egress and CI never should — so what is pinned is the shape: the URL built, the body sent, the JSON mapped onto the answer, the errors told apart, and what the gate refuses.

    It cannot say that a real Ollama answers what its documentation says it does, and it cannot say that any of these models writes a good commit message.

    Every recording is written by hand from a documented schema, so no fixture can carry a key — asserted by a test that reads the fixture file's own bytes back. That test failed against itself the first time, because the needle was a literal the file therefore contained.
