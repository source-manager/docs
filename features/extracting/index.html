    Taking pieces out of a proposal¶

    Licensing — Paid. The extraction itself is stacked-branches; the proposal it opens and the retarget are forge-write. What a licence adds

    "This proposal is too big, take the API change out into its own" is the commonest thing anybody says about anybody else's work, and until this existed the answer was to leave the app for a terminal: a branch cut, checkout -p twice, a force-push, and a proposal retargeted in a browser.

    It is splitting a branch's other verb, and the only one here that moves a branch that already exists. Everything the split writes is a name that was free; an extraction writes one of those and moves one somebody may be reading.

    How it goes¶

    1. On a proposal's page, press Extract. The chip lights, a strip appears above the file list saying what the ticks mean now, and the pane beside it starts drawing this checkout's diff rather than the forge's patch.
    2. Pick what comes out — a file's tick, a hunk, a run of lines, or a commit, whose Take puts every file it touched into the set.
    3. Choose a mode, name the new branch, and press. The extraction is written locally and refuses in its own words if it cannot be.
    4. The propose dialog opens on the new branch — the same push, reviewers, labels and draft tick the ordinary Propose button uses.
    5. Only then is the original branch pushed, and in stacking mode the proposal is retargeted.

    The order cannot be reordered. Until the extracted branch exists on the forge, retargeting names a branch the forge does not have — and a proposal whose branch has lost the extracted code while nothing holds it yet is work that looks deleted. Every failure between the steps gets a sentence, because each leaves a coherent state that is not the one asked for: a refused push leaves both branches here as the extraction left them; a refused lease means somebody has pushed since your last fetch, so the rewrite is here and the forge still has the old branch.

    The three modes¶

    Each is named after what happens to the branch the code came out of, and the whole of the difference is the parent of the one commit that branch is left with.

    Mode The branch's new commit sits on Its tree The push
    Remove the branch's own tip the remainder ordinary
    Rewrite the base the remainder with a lease
    Stack the extracted commit the branch's own with a lease

    Remove is the default because it is the only one that keeps the branch's history: every hash on it survives, the push is an ordinary fast-forward, and the proposal's diff loses the extracted code because a commit on top took it back out.

    Rewrite is what you want when the branch should read as though the extracted code was never on it.

    Stack gives the branch its own tree rather than a synthesis, which makes "the two add up to the branch" true by construction: what it then adds over its new base is exactly the remainder. It is the mode that wants the proposal retargeted, and the only one that asks the forge for anything.

    Both rewriting modes force, and force means a lease. A branch somebody else has moved is refused by name rather than overwritten, and with no remote-tracking ref it refuses as git does. A plain --force is never reached from here — the transport's rule, and the one place you would most regret it.

    The two sides are exact complements¶

    What the branch is left holding is derived from what you picked rather than gathered alongside it, because this is the one thing in the operation that could be quietly wrong: a synthesis that dropped a line produces two branches that both commit, both push, and are both plausible.

    • A file nobody picked is taken whole, being entirely what is left.
    • A file picked whole is absent from the remainder, and absence is right rather than empty: the tree is built from the base, so a file nothing says anything about stays as the base has it — which is precisely "this file's change went elsewhere".
    • A partly picked file keeps every line the pick did not name.

    The guarantee is asserted as blobs compared string for string, not as "something was written".

    It refuses before it writes anything¶

    • A branch another worktree has open is refused by name, with that worktree's path in the sentence. libgit2 refuses it too — but at the second of the two calls a move is, having already written the tree, which reads as "I extracted four files and now every one of them is a staged change".
    • A dirty working tree, where the branch is the one you are on, is refused first and in this app's words naming the file. Untracked files are deliberately not counted: nothing this writes touches a path git does not know about, and refusing over a stray build artefact would make the operation unusable in exactly the repositories it is for.
    • A branch this checkout does not have — which is what a proposal from a fork is — cannot be extracted from, and the chip that starts the mode is absent rather than greyed.
    • Taking everything is refused: that is not an extraction.

    Where the branch is the one you are on, the working tree and the index move with the ref, so you are not left standing on a commit that no longer exists.

    The ticks mean something else while the mode is up¶

    The box beside a file is "I have read this" everywhere else on a proposal's page; while an extraction is being arranged it picks the file. One box with two meanings is a real cost, and the alternative — a second tick in a row that already carries a fold arrow, a status letter, a diffstat and a comment count — is worse.

    What pays for it is that the mode is loud: the chip is lit, the strip above the list says what the tick means and which diff is on screen, and the pane beside it is drawing a different diff. It is a strip rather than a dialog because this takes several minutes and several places, and a thing you can walk away from mid-way must not be possible to lose track of.

    The picking is against your local diff, deliberately. The forge's patch is a different rendering of the same change — its context, its hunk boundaries — so a pick made against it would take out lines nobody chose, silently.

    A commit's Take is a gesture over its files rather than over its own lines, and that is honest rather than lazy: a commit's contribution to a file a later commit rewrote is not in the cumulative diff at all, so claiming to take its lines would be a number that is right about the easy case and confidently wrong about the interesting one.

    Retargeting, and where it is not offered¶

    Re-basing a proposal is not a small thing — it moves the merge base, so the diff every reviewer is reading is a different diff afterwards. It is here for the one errand that cannot be finished without it, it is one named write, and the app sends a base and nothing else, asserted by reading the bytes that go out.

    It is its own capability rather than riding on "can this forge change a proposal's state". Where a forge does not have it, stacking still runs and the dialog says — where the choice is made, not afterwards — that the proposal will have to be retargeted by hand.

    The result is re-read rather than claimed. What a claim would buy is a branch name changing a second early, in exchange for the page having to be right about what else moved: every file in the diff, the file list, the size estimate and every comment's anchor.

    Undoing one¶

    The operation log carries an extract-branch row that offers both writes back: the new branch dropped and the old one put where it was. An inverse that only deleted the new branch would leave the original holding the commit the extraction gave it — the state you are trying to get out of.

    Both ends are guarded. The extracted branch is dropped forced, its commit being a synthesis nothing else reaches, and what earns that is its tip still being exactly where the extraction left it. The original is put back only if it is still there too; a commit made on it since is work this would throw away, so it is refused by name.

    It cannot un-push and it cannot close a proposal, and the row's own sentence says so: if you have already pushed, you get your refs back and still have a proposal to close on the forge.
