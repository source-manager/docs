    Settings¶

    Licensing — Free. Every preference on both pages. Running the interface in another language is localization. What a licence adds

    ⌘, / Ctrl+,, or the button at the end of the workspace bar — and either of those again to leave, because the page has no tab and the key that opens a destination nobody can see a seat for is the key anyone presses again to be rid of it. The button renames itself with what the next press will do, since a toggle whose name never changes is one nobody can find the way out of.

    Everything the app remembers is still a chip, a tick or a dial where it applies, because a control beside the thing it changes is the right way to change it. What this page adds is an answer to "what does this app remember?", and a home for the handful of choices that had none.

    Two pages, chosen by chip¶

    They were one and could not honestly stay one:

    Kept in Applies
    What the app remembers The app's own settings Wherever you are
    What this checkout says One repository's .git/config To everybody who works on it, and gone the moment you open something else

    You could not tell which of the two a row was without reading its sentence to the end, and the answer decides whether what you type follows you to the next repository.

    The second holds the ticket links, the ticket id rules, the expected subject shape, what may be sent to a hosted model, and what signs a commit here.

    It writes this app's own keys and not git's. Overruling gpg.format from a settings page would be this app taking a second view on something every other git tool reads; the keys it does write are ones nothing else has ever heard of. What it draws beside git's own values is the half you cannot see from your own config file — which rules are in force, which came from the forge, and which were dropped and why, since a rule with half of itself missing or a pattern that will not compile is silent everywhere else.

    Eighteen sections in six bands, and a search¶

    Eighteen sections down one column is a list rather than a page: every one names a place, and nothing said which of them somebody with a question about how a commit is written should be looking in.

    And there is a search, because the bands answer "where would that be filed" and never answer "where is the one about whitespace" — the question you arrive with, already knowing the word. It matches the sentence as well as the name, deliberately: the sentences here are as much the deliverable as the switches, and every word worth searching for is far more likely to be in one of them. A section head whose own label matches keeps all of its rows, and a heading with nothing left under it goes.

    The page leads with Appearance and then Type size, which are the two sections that name what every other section is drawn in rather than a place — and the two somebody arriving for the first time has most likely come for, since "this reads small" and "this is too dark" are complaints about the app rather than about a surface.

    Three rows that could only be read are gone: the folder the last repository was created in, how many repositories are registered, and the OAuth client id. Each stated a fact and offered nothing, and a row you can only read is one you scroll past on the way to the ones you came for. The rows that state a count under a section head carrying a Reset stay — those are what the reset puts back.

    Type size¶

    Two dials: the interface and the monospace.

    They are not seven choices but one scale — what a caller means by "tiny" is "two steps below the body" rather than "eleven pixels" — so the offsets stay fixed and the body size is what you set. Nothing on any surface had to be touched to make the whole app resize.

    The defaults moved up a step each, because a size somebody has to go and find in a settings page is a size for the people who already know it is there. One step and not two: every fixed row height in the app was measured against the old numbers, and larger sizes are reachable anyway because the control height is a floor rather than a formula — nothing moves at the sizes the app was designed at, and a button, a chip, a row and the bar all follow past that.

    The monospace is a size of its own and is deliberately not derived from the other, for three reasons in increasing order of cost:

    1. They are read differently — chrome is scanned, a diff is read line after line, and every editor that ships both settings ships them apart.
    2. The mono size is a layout input where the interface size is not: it decides a diff's horizontal scroll range and the row height that makes the diff virtualise at all.
    3. The side-by-side threshold is 55 columns of it, so one dial over both would silently change when a panel is wide enough for two columns as a side effect of a change to the tab bar.

    Three palettes¶

    Nocturne is the default and is untouched — the migration is the absence of a settings key, which is what makes an upgrade look exactly like the app you closed. Slate is the plain dark: neutral greys with no violet cast, for somebody who wants Nocturne's darkness without its colour. Daylight is the light one.

    "Follow the system" is a rule rather than a fourth palette, and it chooses between Daylight and Nocturne — not Slate, because Slate is a deliberate departure from what this app looks like in the dark and having the operating system pick it would be the OS choosing the app's identity. It is live where the platform reports a change.

    What a light theme actually costs¶

    A palette is not fifty colours but a set of seeds and weights: an ink, an accent, five grounds, and then the weights, which is what makes the difference between the three palettes data rather than fifty numbers each.

    The weights are per palette, and that is the whole reason a light theme is work. Ink at 0.55 over Nocturne's ground is 5.2:1 and comfortable; the same weight over Daylight's is 3.5:1 and fails AA for body text. Every rung of Daylight's ladder was measured against its own ground and set so it matches or beats Nocturne's — and the figures are asserted by a test rather than left in a comment, with each floor being Nocturne's own measured value rounded down, so a floor is an observation about the shipped app rather than an aspiration and a new palette has to be at least as readable as the one this app has always had.

    Four things needed real answers rather than an inversion, and each is where a light theme built by swapping two colours fails first:

    • The diff washes. The intra-line word marks are a step weaker on Daylight rather than stronger — they sit behind the syntax colours, and on a light ground a wash moves the paper away from the ink rather than towards it. The gap wash drops from 0.16 to 0.055: "a shade deeper than the ground" is the rule, and a sixth of black is a bruise on white.
    • The four verdicts. Nocturne's are pastels tuned not to vibrate on its ground; the same four on white are unreadable. Every one of the twelve verdict-on-ground pairs clears AA outright — a lower bar than the ink ladder's on purpose, because "is anything broken" is the only question the Checks tab is opened with.
    • Syntax highlighting, with the hue assignments kept — keyword takes the accent, strings green, numbers red — so you read the same code in the same colours at the value that ground needs.
    • The graph's lanes, declared per palette rather than derived, because the ramp positions that give six distinguishable lanes on a dark ground give Daylight one duplicate and one invisible.

    The lane guard measured the wrong thing for a while

    Its floor was a contrast ratio, which compares lightness — so two weights of one ink differ in exactly that and pass, while two real hues at one lightness score 1.00 and are unmistakable. The test licensed the ramp it existed to guard, and rendered, four of the six "lane colours" were duplicates of another. It is a perceptual colour distance now, and run against the old ramp it names four pairs as the same colour.

    Which figures are computed¶

    A reset and a sentence; the ticks live on the metrics page where the price of each group is legible. It is its own reset entry rather than a line in "metrics" — that one is the window the figures cover, and one reset over both would put your period back while you were turning a card on.

    Moving between places¶

    Its own section, because there is no other it belongs in: everything else on that page is about how something is drawn or read, and this is about how the app is driven.

    It holds the two-finger swipe, whose row is absent where the platform has no such gesture — and the preference is stored and reported as a changed section on every platform all the same, because a choice made on a laptop should not be forgotten because the app was last opened on a desktop.

    Language¶

    The interface in something other than English. French, partly filled, so far.

    The choice is applied at the next launch, and the row says so — which is the decision worth arguing, because the other answer is reachable. Re-evaluating every binding that holds a translated string would change the ~1900 strings in the interface for one call and no edit to any of them.

    What is not cheap is the other half: forty-nine sentences are produced during a walk rather than computed on read — why a file history is empty, why a comparison stopped, what a rebase plan summarises. Each is produced during a walk that is batched against a time budget precisely because it cannot be run again casually, so recomputing them means re-running those walks, and not recomputing them means a window half in each language — with the untranslated half being exactly the sentences that say why a list is empty, which is the state you are in front of when you have most reason to read carefully.

    What makes waiting acceptable is that the row is honest about it, and while the chosen language is not the one on screen it names the one that is — "…until then the words on screen are French". A drop-down showing one language over a window drawn in another, with nothing said, is a control that reads as broken.

    Each language is drawn by its own native name, because somebody looking for their language in an app they cannot currently read needs the one string they are certain to recognise.

    Two things are never translated

    A printed git command, because its output is meant to be pasted into a shell and a translated word in it is not a degraded answer but a command that does not run. And a control's git verb, which is the palette's search index — a translated stash push silently stops the palette finding it for anyone who searches the vocabulary, while its title is prose and is translated.

    Both are asserted by tests, the second read off the source, because it is a fault in a declaration and is invisible at runtime until a catalogue happens to translate that verb.

    Where it all lives¶

    The app's own settings are QSettings — one key per choice, including one key per panel size and one per figure group, so the file stays readable and migration is an absence per key: a build that adds a group finds no key for it and uses that group's own default, where a single stored list would have had to be read as complete.

    Three things are JSON beside it rather than in it, because a growing list of records in a settings file is an abuse of the shape: the operation log, the action sequences, and the review draft. All three are written through on every edit — a save deferred to quit is a save that does not happen when the app is killed — and all three re-read immediately before writing, because two launches of the app used to erase each other.

    The forge's answers are a database, which earns itself by answering three differently-shaped questions and by being a cache: its schema carries a version and a bump throws every row away, which is right for rows whose entire replacement cost is a round trip.
