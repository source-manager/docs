    The git GUI field, and where this one sits¶

    A survey of fourteen git clients — the ones people actually use — against this one.

    Read the dating before the ratings

    The field was compiled in August 2026 from vendor feature pages, product documentation and current reviews. This app's own column has been revised since and the others have not, so a competitor's twelve months of releases are not in it.

    Treat the matrix as "what this app can do", measured honestly, and "what they could do a year ago", measured from their own marketing. Feature sets move, and the paid/free splits move fastest of all.

    Where it stands¶

    It is in the top tier on the core git surface, and ahead of the field on several things nobody else does.

    Measured on what a git client is fundamentally for — reading history, reading a diff, staging precisely, and rewriting history safely — this app sits with Fork, Tower, SmartGit and Magit rather than with the free clients it is priced like. Line-level staging, line-level revert, a previewed rebase plan, per-hunk three-way conflict resolution, a full submodule lifecycle, subtrees, worktrees, a stash editor, and a compare surface that tells two-dot from three-dot are collectively a set that only SmartGit and Magit match — and each of those charges or demands Emacs.

    Five things that are effectively unique¶

    1. Honest undo. Everyone else either has no undo or sells "Undo everything". This app types every operation and offers a button only where one can be kept, with file-level backups taken before the four writes that destroy content held in no git object. GitButler's per-operation snapshots are the only comparable safety net, and it does not distinguish what is recoverable from what is not. → Undo, backups and the log
    2. Teaching the command line. What you would have typed, printed beside the decision. Sublime Merge shows commands as it runs them; nothing else in the field treats the CLI vocabulary as the search index for its own palette.
    3. Repository insights. History metrics, DORA with the definition printed beside every figure, team and per-person figures with the caveat kept, and CI health. No desktop client in this survey has anything like it; this is normally a separate SaaS product. → Repository metrics
    4. The keyboard model. A palette and a two-press, usage-ranked hint overlay, with an audit test that fails when a control registers in neither route. Only Magit and Lazygit are comparably keyboard-complete, and neither is discoverable the same way.
    5. Forge review depth with a local draft. Reading a proposal, writing a review over minutes, and submitting it in one request — with the draft surviving the network, the app closing, and signing out. Every other client that reviews drafts on the server. → Reviewing a proposal

    Plus a set of correctness details the field routinely gets wrong: a virtualised diff that survives a ten-thousand-line hunk, a binary change reported as a kind rather than "no textual changes", a working-tree watcher, transport off the interface thread with one operation at a time, and contrast-verified palettes.

    Two smaller ones worth naming because nobody else does them: a commit subject inferred from the changed paths and the log with each inference stating its basis — every competitor's suggestion is a model's, and states nothing — and that inference drawn beside the generated draft rather than instead of it, where everyone else ships one or the other.

    Where it is behind¶

    Coverage is no longer the question; evidence is, and that is worth naming plainly.

    The five gaps an earlier revision of this survey identified — Windows, Git LFS, commit signing, one forge, and no custom-command escape hatch — are closed, along with bisect, git-flow, external merge tools, patch import and format-patch, issue links, graph drag-and-drop, git notes, sparse checkout, shallow clone, a keychain, stacked branches, a second window, image diff modes, and AI.

    What is left is short enough to state in one sentence: no Azure DevOps, no non-git VCS, no plugin API, no embedded terminal, no shell integration, no partial clone, no agentic AI — and five of those seven are recorded decisions rather than work outstanding.

    The residual weakness is not a feature

    Nothing Windows has ever been executed. The CI job proves the tree compiles, links and passes headless under MSVC, and says nothing about window chrome, native menus, file dialogs, high-DPI, or drive letters as a user types them.

    GitLab and Bitbucket have never had an answer from a live instance. Their tests pin the shape of the requests and the mapping, which is a real guarantee and not the one a user cares about.

    X.509 signing, both keychain backends, the sparse verbs and every AI provider are implemented and unexercised.

    A competitor that ships to Windows every week has something this does not, and it is not a feature — it is a decade of people running it. The honest summary is that the capability gap is closed and the proving gap is now the whole of the remaining distance.

    The one-paragraph version¶

    On feature coverage this app now leads the field it was compared against, and it keeps the five things nothing else does: honest undo that distinguishes what can be recovered from what cannot, printing the git command you would have typed, repository and DORA metrics that are normally a separate product, a two-press usage-ranked keyboard model with an audit that fails when a control is reachable by neither route, and a review draft that survives the network, the app closing and signing out. Against GitKraken's and GitLens's free tiers it is not close, since both charge for interactive rebase, worktrees, the graph and multi-repo work that is unconditional here. What it does not have is evidence — Fork, Tower and SmartGit have each shipped to real users on three platforms for years, and that is a different kind of claim from a green suite.

    The survey's own citations are kept in COMPARISON.md in the repository, which is where this section is derived from.

    Two ratings that survey got wrong in its first pass are corrected there and here: Fork and Sourcetree have no AI features. The earlier partial rating for each came from review sites summarising each other rather than from either product, and Sourcetree has an open request for it — which is the opposite of shipping it. That is worth recording rather than quietly editing, because it is the same failure this document warns about elsewhere: a survey is only worth the evidence attached to it, and an aggregator is not evidence.
