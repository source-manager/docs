    Getting started¶

    There is no installer yet, on any platform. What the release pipeline produces is a runnable build rather than a distributable one, so getting the app is either downloading a release artifact or building it — both are documented in Installing.

    Once it is running, three pages cover finding your way:

    • :material-download: Installing

      Dependencies, cmake -B build ., and the install rules per platform.

    • :material-view-dashboard-outline: A tour of the window

      The breadcrumb, the tab bar, the operation banner, and the nine destinations.

    • :material-keyboard: Keyboard and the palette

      ⌘K, the two-press hint overlay, ⌃Tab, and moving back and forward.

    The first five minutes¶

    1. Register a repository. The app opens on the fleet page. Press Add ▾ and pick one of the four ways in: Import repository for a checkout already on disk, Clone, New repository, or Scan a folder to find every checkout beneath one directory at once. See The fleet.
    2. Open it. Press the card. The whole tile is the target, not the small button in the corner.
    3. Read the history. The History tab opens on your own branch's tip rather than at the top of the list, with that commit's files and diff already on screen.
    4. Stage something. On Changes, tick a file, or select lines in the diff and stage those. Space stages or unstages whatever is picked.
    5. Learn one keyboard route. Tap ⌘ (or Ctrl) once and let go — every primary control on screen grows a letter. Press the letter. Tab reveals the long tail; Esc puts them away.

    Two things that surprise people¶

    The branch crumb does not check out. Choosing a branch in the breadcrumb's picker narrows the history to it. That is what clicking a branch has always meant here, the picker says so in as many words, and people rely on it. Checking out lives on Manage → Branches, where the row also tells you what the checkout would overwrite before you press it.

    A control that cannot apply is not drawn. Not greyed — absent. So a repository with no remote has no Push button rather than a dead one, and the first reading of a thinner-looking window is usually that a verb does not apply here rather than that it is missing. The exceptions are deliberate and few: the transport buttons grey while a transfer is running (the verb applies, it is just busy), and an AI control with no provider configured stays live so that pressing it can explain itself.
